## 沙箱系统代码分析（未修改代码）

用户要求分析当前多智能体项目的沙箱系统实现，重点确认"是否每次文件操作都创建新镜像/容器"。

### 关键结论
- **技术栈**：OpenSandbox SDK，底层 Docker 容器，直接拉取公共镜像 `python:3.11-slim`（不构建镜像）。
- **默认 provider**：`OpenSandboxProvider`（config.yaml:77），非 LocalSandboxProvider。
- **每次文件操作都新建容器**：`_get_sandbox()`（sandbox_tools.py:39）每次工具调用都执行 `provider.acquire()`，而 `OpenSandboxProvider.acquire()`（open_sandbox_provider.py:256-268）直接 `OpenSandboxClient.create()` 新建容器，无缓存/池化/复用。
- **容器泄漏缺陷**：`release()`（open_sandbox_provider.py:270-276）已定义 `kill()+close()`，但生产代码 7 个工具均 acquire 后从不 release，容器靠服务端 `timeout_minutes: 30` 超时回收。
- **无沙箱池、无预热机制**。

### 核心文件
- `harness/services/sandbox_provider.py` — Sandbox/SandboxProvider 抽象 + 单例工厂
- `harness/services/open_sandbox_provider.py` — Docker 容器实现（问题所在）
- `harness/services/local_sandbox_provider.py` — 宿主机直读直写实现（轻量，默认未启用）
- `harness/tools/sandbox_tools.py` — 7 个文件/Shell 工具入口
- `harness/middleware/sandbox.py` — 仅注入上下文，不管生命周期
- `harness/config.yaml:72-92` — 沙箱配置

## 给出修复方案与修改提示词

用户进一步要求分析原因 + 解决方案 + 完整修改提示词。

### 原因（3 层）
1. 工具层：`_get_sandbox()` 每次都 acquire，无缓存。
2. 中间件层：`SandboxMiddleware` 只实现 `awrap_tool_call` 注入 context，未实现 `abefore_agent`/`aafter_agent` 来 acquire/release。
3. Provider 层：`OpenSandboxProvider.acquire` 直接 create 容器，无按 thread_id 复用。

### 方案：生命周期上移到 agent turn 粒度
- `sandbox_tools.py`：新增 `_current_sandbox` ContextVar + `acquire_sandbox_for_turn`/`release_sandbox_for_turn` helper；`_get_sandbox()` 优先读 ContextVar。
- `sandbox.py`：`SandboxMiddleware` 实现 `abefore_agent`(acquire) + `aafter_agent`(release)。
- `open_sandbox_provider.py`：加 `_cache: dict[thread_id, OpenSandbox]` + `_cache_lock` 双保险，同 thread_id 复用。
